# Separate Volatility and Direction Targets (Sub-project 3b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add targets `vol3` (quiet/normal/wild) and `dir2` (down/up) beside `move3`, through evaluation, storage, reports, training, `tb predict` and the dashboard.

**Architecture:** A `Target` registry in `ml/targets.py`; everything that assumed three fixed classes takes the class list from the target; predictions are stored positionally (`p0, p1, p2`).

**Tech Stack:** as sub-project 3 (pandas, NumPy, scikit-learn, xgboost, psycopg, Typer, FastAPI).

**Spec:** `docs/superpowers/specs/2026-10-08-targets-3b-design.md`

## Global Constraints

- `VOL_QUIET = 0.5`, `VOL_WILD = 1.25`, `u = atr_pct_t · √H`; `vol3`/`dir2` `label_set = 1`; `move3` unchanged.
- Default target everywhere is `move3`; old runs and saved `move3` models keep working.
- Same NA rule for every target: missing future bar in the horizon or NULL `atr_pct_t`.
- No advice words in any output.

## Review Focus

1. **Old `move3` runs stored before the migration** must read back and render unchanged → test in Task 3.
2. **A two-class run** (`p2` NULL) through summarise, report, dashboard SVGs and diagnose refusal → tests in Tasks 3, 4, 6.
3. **`tb predict` with only `move3` models saved** (the user's current state) → prints move3 and a skip line per missing target, exit 0 → test in Task 5.
4. **A `vol3` model loaded for `dir2`** (wrong target in meta) → ArtifactMismatch → test in Task 5.
5. **A fold whose training rows lack one `vol3` class** (rare "wild") → still `n` columns → test in Task 2.

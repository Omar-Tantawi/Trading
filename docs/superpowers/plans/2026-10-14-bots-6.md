# Bot Monitoring v1: Bots vs Holding (Sub-project 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tb bots add/update/stop/undo/delete/list/show` record the user's spot grid bots from typed-in numbers and compare each with holding the coin; a dashboard tab shows the same.

**Architecture:** New `bots/` package: pure `times.py`, `compare.py`, `report.py`; DB `store.py`, `prices.py`; migration 008; CLI group `bots_app`; dashboard `/api/bots` and tab.

**Tech Stack:** Python 3.13, psycopg, Typer, FastAPI.

**Spec:** `docs/superpowers/specs/2026-10-14-bots-6-design.md`

## Global Constraints

- Profit typed in = the app's **Total profit** (USDT).
- Hold value = `invest × (1 − fee) × P(T) / P(start)`; fee stored per bot at `add`.
- Price at t = open of the latest 1m candle with `open_time ≤ t`, at most 10 min before t.
- Typed times: PC local time by default, `--utc` for UTC; stored UTC; echoed.
- "level" when |bot − hold| < 0.01 USDT.
- No advice words in any output; `bots*` in the pyproject package list; `bots`, `bot_updates` in the test DB delete list.

## Review Focus

1. **Undo of a stop update** reopens the bot → test in Task 2.
2. **Coin without stored prices / gap near a time** → "unavailable" with the reason, not a crash, and excluded from totals → tests in Tasks 1 and 3.
3. **Update rules** (before start, before previous, future, after stop, profit ≤ −invest) → tests in Task 2.
4. **Local-time parsing** independent of the test machine's zone → test in Task 1.
5. **Bot with no updates** → "no update yet", excluded from totals → tests in Tasks 1 and 4.
